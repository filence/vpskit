## 证据分层

本方案统一使用以下表述，避免把规划写成已实现能力：

- **已确认基线**：当前源码、公开 Release、CI 或 Debian 13 amd64 实机已经有证据；
- **目标设计**：有明确实现路径，但尚未进入当前产品；
- **实验候选**：上游或某些客户端可能支持，仍需固定版本和真实客户端验证；
- **禁止承诺**：无法稳定保证的结果，例如 WARP 必然解锁 AI、规则必然无误杀、KV 全局原子切换。

## 修订后的核心结论

VPSKit 后续应演进为：

> 面向个人少量 VPS 的、低资源、可回滚、支持持续客户端交付的模块化生命周期管理工具。

本次审查保留“自动订阅、多客户端、分流去广告、恢复、多 VPS、WARP 和系统模块”的产品方向，但调整实现顺序：

```text
本地 Renderer 与元数据基础
→ 单 VPS 订阅最小闭环
→ 规则与去广告
→ 可移植加密快照
→ 多 VPS 聚合与更多客户端
→ Hysteria2 增强
→ WARP AI 出站
→ 新协议
→ 系统模块
```

所有新增功能必须满足：

1. 先定义状态、接口、回滚和验收，再开放菜单入口；
2. 不把 Cloudflare 管理级 API Token 分发到每台 VPS；
3. 不把 Workers KV 的最终一致性描述成全局原子发布；
4. 不把上游新版本字段描述成当前 `sing-box v1.13.14` 已具备；
5. 未经真实客户端验证的 Renderer 只能标为 experimental；
6. 高风险模块默认关闭，可独立安装、禁用、回滚和卸载；
7. 对 1C1G/10G 环境给出实测资源影响，而不是估算承诺；
8. 失败时优先保留当前可用节点、上一修订和至少一个可恢复备份。

## 安全提示

项目根目录的本机忽略文件 `.前期环境须知.md` 是用户明确提供的授权凭据入口，不属于本方案包，也不得提交或打包。Agent 可在用户授权的 VPSKit/VPS/Cloudflare 范围内直接使用其中凭据；本地读取不等于外泄，不要求仅因此轮换。使用时不得回显、不得写入源码或日志、不得扩大操作范围，具体见 `11-前期材料与环境准备.md`。
