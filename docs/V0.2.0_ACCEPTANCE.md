## 1. 结论

结论：`PASS`（本报告列出的 Debian 13 amd64、Cloudflare Workers/KV、Windows 11 客户端范围）。

`v0.2.0-lab.1` 已在一台 Debian 13 amd64 单 VPS 上完成升级。Cloudflare 预发布和正式订阅后端均已创建；正式后端由 VPS 的节点级发布凭据发布 `mihomo`、`v2rayn` 和 `manifest` 三类产物。Windows 11 上的 Clash Verge Rev 与 v2rayN 已由用户完成订阅导入和从 r0003 到 r0004 的手动“更新订阅”验收。

本报告不公开域名、订阅读取 Token、节点发布 Secret、Cloudflare 管理 Token、VPS 地址或协议凭据。

## 3. 部署与发布证据

1. 本地 Worker 测试、`go mod verify`、`go test ./...` 均通过；签名发布包 `v0.2.0-lab.1` 通过 `bundle verify`。
2. Cloudflare 管理 Token 仅存在于本地受限环境，用于创建 Worker、KV、Worker Secret 和 Custom Domain；VPS 未保存该管理 Token。
3. Worker 为每台 VPS 使用独立 `node_id` 发布身份、HMAC 签名、时间窗和 nonce；客户端仅使用独立 read-token 路径读取订阅。
4. VPS 上 `subscription configure`、`subscription publish`、`subscription status` 均返回 `PASS`，并完成远端回读。
5. 初始修订 r0003 成功发布；节点显示名变更后自动发布 r0004；恢复原显示名后正式后端自动发布 r0005。

## 4. HTTP 与客户端验收

### 4.1 订阅 HTTP 行为

- `GET /s/<read-token>/mihomo`、`v2rayn`、`manifest`：均为 `200`；
- `HEAD`：`200`，包含客户端修订和 ETag；
- 带 `If-None-Match` 的条件 GET：`304`；
- r0003 与 r0004 的 Mihomo 产物摘要不同，r0004 含预期的新节点显示名；
- 正式 r0005 回读通过，三类产物均为完整修订。

### 4.2 Windows 11 手动客户端验收

用户在 r0003 导入订阅 URL 后，执行客户端“更新订阅”。服务端将节点显示名修改为 `VPSKit-订阅-r0004` 并自动发布 r0004；用户确认以下两项均通过：

| 客户端 | 结果 |
|---|---|
| Clash Verge Rev v2.5.2 / Mihomo v1.19.29 | 通过 |
| v2rayN v7.23.1 | 通过 |

静态 YAML/TXT 仅作为离线回退；客户端自动更新使用明确的 Mihomo 或 v2rayN 订阅 URL，不使用不稳定的 `auto` User-Agent 入口。

## 5. Token 轮换与吊销

正式订阅读取 Token 完成以下序列：

1. 轮换为新 Token，配置 24 小时重叠窗口；
2. 在重叠窗口内，旧 Token 与新 Token 均返回 `200`；
3. 通过 `revoke-read-token` 吊销初始 Token；
4. Workers KV 收敛后，旧 Token 返回 `404`，新 Token 保持 `200`。

这是最终一致性存储的预期语义：命令成功后存在短暂传播窗口；验收以“旧 Token 404、新 Token 200”收敛结果为准，不宣称全局瞬时原子吊销。

## 6. 回滚与清理

- 原 v0.1.1 CLI 已保存于 VPS 受管备份目录；
- r0004、r0005 节点变更均创建受管备份与事务 ID；
- 运行中的 Xray/sing-box 未因 CLI 升级或订阅配置而重启、停止或改变监听端口；
- VPS `/root` 下的临时发布包、临时节点凭据和客户端 Token 文件已删除；
- 正式订阅当前使用 VPS 内部 `0600` Secret 文件和本地受限客户端地址文件。

## 7. 已知边界

- 当前客户端 GUI 证据绑定 Windows 11、Clash Verge Rev v2.5.2/Mihomo v1.19.29 和 v2rayN v7.23.1；
- Loon、Shadowrocket、Android 客户端、WARP、多 VPS 聚合、加密快照和长期资源观测不属于本次通过范围；
- Workers KV 为最终一致性，发布/回滚/Token 吊销均可能经历短暂传播窗口；
- 当前为 `v0.2.0-lab.1` 实机验收，不等同于公开 GitHub Release；公开版本需另行完成 CI、提交、版本标签和发布门禁。

## 6. 后续增量：v0.2.2-lab.2 受管规则 r0008

在相同 Debian 13 amd64 VPS 与相同 Windows 11 Clash Verge Rev v2.5.2 / Mihomo v1.19.29 环境中，已完成以下增量验收：

1. 规则源只读测量：20 个 ACL4SSR、MetaCubeX Google 与 anti-AD 文件总计 `1,120,707` 字节，Base64 估算 `1,494,276` 字节，适配 2 MiB 发布上限。
2. `vpskit rules refresh --yes` 下载并 SHA-256 记录 20 个源，写入受管 revision `2`，主状态切换为 `source_mode=managed`。
3. 第一次自动发布受旧 20 秒 HTTP 等待限制而标记 `DEGRADED`，未影响 Xray/sing-box；发布器升级至 `v0.2.2-lab.2` 的 90 秒等待后，同一 r0008 成功重发。
4. `subscription publish` 和 `subscription status` 均返回 `PASS`，r0008 含 Mihomo、v2rayN、manifest 和 20 个规则 target，全部完成远端回读。
5. 用户已手动确认 Clash Verge Rev 对 r0008 的更新、切换和实际使用均通过。

该增量不代表规则内容永久固定：每次 `rules refresh` 都从指定上游重新获取候选内容，生成新的可追溯缓存 revision；未执行刷新时客户端继续读取当前完整修订。
